# Study Assistant Chatbot — Implementation Plan

## Overview

The chatbot in `ResourcesTab.tsx` allows students to have a contextual conversation about their uploaded study materials. Instead of re-sending entire PDFs on every message, we use **Retrieval-Augmented Generation (RAG)** — the concepts already extracted and embedded in the `concepts` table are used as the knowledge base for the AI to answer questions.

---

## AI Model Decision

| Concern | Choice | Reason |
|---|---|---|
| **Chat model** | **Groq — `llama-3.1-8b-instant`** | Extremely fast and lightweight. Since we already use the heavy 70b model for flashcards, using the 8b model here is perfect for chat and saves token limits. |
| **Embedding** | **Gemini — `gemini-embedding-001`** | **Note on Gemini 1 vs 2:** Because your current database already contains vectors generated by `gemini-embedding-001` (when the documents were first uploaded), we *must* use the exact same model to search. If we used `002` for the chat, the math wouldn't match up and the search would fail. If you want to upgrade to `002` later, we would have to wipe the database and re-parse all PDFs. |
| **Streaming** | Yes | **What this means:** Normally, you have to wait 5-10 seconds for an AI to write a full paragraph before it shows up on screen. "Streaming" means we send the text to your screen one word at a time, exactly as the AI is generating it (just like ChatGPT). It prevents the user from staring at a loading spinner. |

> We do **not** use Gemini for the chat responses themselves because Groq is **significantly faster** (sub-second first token), which is critical for a good chatbot UX. Gemini is only used for embedding the student's query.

---

## Architecture: Hybrid RAG System

To address your excellent question: *"If the student asks to summarize the entire document, does the bot only retrieve 8 concepts?"*

If we only used embeddings, yes, it would only retrieve 8 concepts and give a terrible summary! To fix this, we will use a **Hybrid Approach**:

1. **Specific Questions ("What is RA 10175?"):** We use the embedding model to search and retrieve the Top 8 most relevant concepts. This is fast and saves tokens.
2. **"Summarize" / "Explain Simply" buttons:** We completely bypass the embedding model. We will fetch **ALL** concepts for the selected document directly from the database and feed them all to the AI. This ensures the summary covers the entire document.

```
Student action determines the flow:
        ↓
IF specific question: 
  → Embed query → Find Top 8 concepts via cosine similarity
IF clicked 'Summarize': 
  → Fetch ALL concepts for the selected files directly
        ↓
Assemble concepts as CONTEXT
        ↓
Groq llama-3.1-8b-instant streams the response back token by token
        ↓
Backend saves the conversation to the `chatbot_logs` table
```

## Proposed Changes

### Backend

---

#### [NEW] `server/routes/chat.routes.ts`

A brand-new route file dedicated to the chatbot. Contains:

**`POST /api/chat`**

Request body:
```json
{
  "message": "What is RA 10175?",
  "material_ids": ["22a83138-...", "32b615c9-..."],
  "history": [
    { "role": "user", "content": "Hello" },
    { "role": "assistant", "content": "Hi! Ask me anything..." }
  ]
}
```

Logic:
1. Validate request body with Zod
2. Embed the student's message using `generateEmbedding()` (Gemini)
3. Call a new Supabase RPC function `match_concepts` to retrieve the top 8 most relevant concepts from the selected materials using cosine similarity
4.   - The full conversation history (we will use the **last 4 messages** to save tokens during development)
   - The student's query
5. Call `groq.chat.completions.create()` with **`stream: true`**
6. Save the user's prompt and the AI's final response into the **`chatbot_logs`** table in the database for persistence.
7. Pipe the streaming response back to the client using `res.write()` with `text/event-stream` (Server-Sent Events)

#### [NEW] Supabase Migration — `match_concepts` RPC

We need a PostgreSQL function to do the vector similarity search. This will be executed once as a migration:

```sql
CREATE OR REPLACE FUNCTION match_concepts(
  query_embedding vector(3072),
  material_ids    uuid[],
  match_count     int DEFAULT 8
)
RETURNS TABLE (
  term        text,
  definition  text,
  similarity  float
)
LANGUAGE sql STABLE
AS $$
  SELECT
    term,
    definition,
    1 - (embedding <=> query_embedding) AS similarity
  FROM concepts
  WHERE material_id = ANY(material_ids)
    AND embedding IS NOT NULL
  ORDER BY embedding <=> query_embedding
  LIMIT match_count;
$$;
```

> [!NOTE]
> This uses the `<=>` (cosine distance) operator from `pgvector`. Since your vector dimension (3072) exceeds the pgvector HNSW index limit of 2000, this is a sequential scan — acceptable for student-scale data sets.
